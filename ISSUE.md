# Generation time and output explode when a graph with shared dependencies is reached through a `Func<T1, T>` delegate

**Pure.DI 2.5.6**, .NET SDK 10.0.402, macOS. Repro project attached (`dotnet build`, about 30 s; see the table for larger sizes).

A service layer where each service depends on the two previous ones (`S2(S1, S0)`, `S3(S2, S1)`, ...), all **singletons**, bound as usual. Resolved directly as a root (`Root<S28>`) it builds in 2 s and generates about 700 lines. Resolved through a `Func<string, S20>` delegate (the `string` only reaches `S0`), the same graph takes 30 s to generate, and each extra level multiplies the time by about 3 and the output by about 1.6. From 23 classes on, the build either fails or does not finish.

## Minimal code

21 classes; the attached project is this shape with `S20`.

```csharp
using Pure.DI;

var composition = new Composition();
Console.WriteLine(composition.Root.GetType().Name);

public sealed class S0(string label) { public string Label => label; }
public sealed class S1(S0 s0);
public sealed class S2(S1 a, S0 b);
public sealed class S3(S2 a, S1 b);
// ... same pattern ...
public sealed class S20(S19 a, S18 b);
public sealed class Top(Func<string, S20> factory) { public S20 Make(string label) => factory(label); }

partial class Composition
{
    private static void Setup() => DI.Setup(nameof(Composition))
        .Bind<string>().To(_ => "default")
        .Bind<S0>().As(Lifetime.Singleton).To<S0>()
        .Bind<S1>().As(Lifetime.Singleton).To<S1>()
        // ... every Sk as Singleton ...
        .Bind<S20>().As(Lifetime.Singleton).To<S20>()
        .Root<Top>("Root");
}
```

## Expected

Generation time and output in the order of what the same graph costs as a direct root: a couple of seconds and one initialisation block per singleton (there are 21 of them).

## Actual

| classes | root is `S_N` directly | root is `Top(Func<string, S_N>)` | generated `Composition.g.cs` through the `Func` |
|---|---|---|---|
| 15 | | 3 s | 8,269 lines, `S0` initialised at 610 places |
| 17 | | 3 s | 21,191 lines, 1,597 places |
| 19 | | 6 s | 55,018 lines, 4,181 places |
| 21 (attached) | 2 s | 29 s | 143,575 lines, 10,946 places |
| 23 | | 5 min 37 s, then `error CS0204: Only 65534 locals, including those generated by the compiler, are allowed` | 375,417 lines, 28,657 places |
| 25 | 2 s | killed after 7 min | |
| 29 | 2 s, 683 lines | killed after 7 min | |

The singleton `S0` is initialised once per distinct path from `S_N` down to `S0` (the Fibonacci numbers in the last column) instead of once, and every level of the graph roughly doubles the time on top of that. The generated lambda of the delegate ends up with tens of thousands of locals.

On a real application (about 2,500 bindings, view models created through `Func<...>` factories, a shared service layer under them) the generator ran for hours without completing.
